# V3.1 数据层迁移

> 本文档记录 V3.1（`attendance-v3/`）将 V2.0 的数据层从 IndexedDB/Dexie 迁移到 SQLite + REST API 的完整方案。前端业务代码保持零改动是本迁移的核心约束。

## 迁移目标

V2.0 是纯前端应用，数据存在浏览器 IndexedDB（Dexie.js 封装）。该架构的问题是：数据随浏览器隔离、无法跨设备同步、无法服务端持久化。V3.1 的目标：

1. **保留 V2.0 全部前端代码**（HTML 页面、Vue 应用、业务逻辑、Excel 解析、规则引擎、UI 样式）
2. **只替换数据层**：`Store` 对象的 IndexedDB CRUD 操作改为 HTTP REST API 调用
3. **后端**：Python `http.server` + SQLite，零第三方 Web 框架

## 迁移策略

核心思想：**保持接口签名不变，替换内部实现**。

V2.0 所有业务代码通过 `Store` 对象访问数据（而非直接操作 Dexie）。V3.1 创建 `shared/api-store.js`，实现与 `db.js` 中 `Store` **完全相同的方法签名**，内部从 Dexie 表操作改为 `fetch` 调用后端 REST API。

```
V2.0: 业务代码 → Store.xxx() → Dexie → IndexedDB
V3.1: 业务代码 → Store.xxx() → fetch → /api/store/* → SQLite
```

## 逐项差异对照

### 1. Store 接口映射

| Store 方法 | V2.0 实现（Dexie） | V3.1 实现（REST） |
|-----------|--------------------|--------------------|
| `bulkPut(table, records)` | `DB[table].bulkPut(records)` | `POST /api/store/{table}/bulk` |
| `clearTable(table)` | `DB[table].clear()` | `DELETE /api/store/{table}` |
| `getAll(table)` | `DB[table].toArray()` | `GET /api/store/{table}` |
| `getByIndex(table, idx, val)` | `DB[table].where(idx).equals(val)` | `GET /api/store/{table}?index=&value=` |
| `getByRange(table, idx, lo, hi)` | `DB[table].where(idx).between(lo, hi)` | `GET /api/store/{table}/range?index=&lower=&upper=` |
| `getByKey(table, key)` | `DB[table].get(key)` | `GET /api/store/{table}/{key}` |
| `put(table, record)` | `DB[table].put(record)` | `POST /api/store/{table}` |
| `deleteByKey(table, key)` | `DB[table].delete(key)` | `DELETE /api/store/{table}/{key}` |
| `resetAllData()` | 前端遍历清空 13 表 + 重建默认 | `POST /api/store/reset` |

### 2. 认证迁移

| 维度 | V2.0 | V3.1 |
|------|------|------|
| 校验位置 | 前端硬编码 `admin/admin123` | 后端 `POST /api/auth/login` |
| 凭证存储 | `localStorage['attendance_auth'] === 'true'` | `sessionStorage.token`（JWT） |
| 函数形态 | 同步 `Auth.login()` | 异步 `Auth.login()`（返回 Promise） |
| 请求鉴权 | 无 | 每次请求附加 `Authorization: Bearer <token>` |

### 3. 复合索引查询降级

V2.0 使用 Dexie 复合索引；SQLite 中未建复合索引，改为单列索引 + JS 内存过滤。共 4 处：

| 位置 | V2.0（Dexie） | V3.1（Store API） |
|------|---------------|--------------------|
| `rules.js calculateMonth` 排班查询 | `DB.schedules.where('[employeeNo+year+month]').equals([emp,y,m]).first()` | `Store.getByIndex('schedules','employeeNo',emp)` + 内存 `find(year && month)` |
| `rules.js _updateCarryOver` 结余查询 | `DB.carry_over.where('[employeeNo+month]').equals([emp,m]).first()` | `Store.getByIndex('carry_over','employeeNo',emp)` + 内存 `find(month)` |
| `rules.js getResultDetail` 详情查询 | `DB.attendance_results.where('[employeeNo+date]').equals([emp,d]).first()` | `Store.getByIndex('attendance_results','employeeNo',emp)` + 内存 `find(date)` |
| `attendance.html` 排班缺失检测 | `DB.schedules.where('[employeeNo+year+month]').between([0,y,m],['\uffff',y,m]).count()` | `Store.getAll('schedules')` + 内存 `filter(year && month).length` |

> 性能影响：schedules/carry_over/attendance_results 数据量通常数百到数千行，内存过滤可接受；若数据量增大需在后端增加多条件 WHERE 支持。

### 4. 导出服务合并

| 维度 | V2.0 | V3.1 |
|------|------|------|
| 服务形态 | 独立进程 `export_server.py`（端口 8000） | 合并进 `server.py`（端口 8001） |
| 认证 | 无鉴权 | 需 Bearer token |
| XLSX 生成 | openpyxl | openpyxl（`handlers/export.py`，逻辑同 V2.0） |
| 数据来源 | 前端读取 IndexedDB 后 POST | 前端读取 SQLite（经 REST）后 POST |

### 5. 初始化逻辑迁移

| 初始化项 | V2.0 | V3.1 |
|----------|------|------|
| attendance_config 默认值 | `db.js startDB()` 前端执行 | `database.py _init_settings()` 后端执行 |
| 默认导出模板（17 字段） | `db.js initDefaultSettings()` | `database.py _init_settings()` |
| 触发时机 | 页面加载时（前端） | 首次启动/重置后（后端） |

## 后端数据模型

- **存储**：SQLite 单文件 `server/data/attendance.db`
- **表结构**：13 张表，字段名与 V2.0 IndexedDB 完全一致（camelCase，如 `employeeNo`、`leaveHours`、`workDays`）
- **连接配置**：WAL 模式、`busy_timeout=5000`、`synchronous=NORMAL`、`foreign_keys=OFF`
- **JSON 字段**：`workDays`、`fields`、`sourcePunchIds` 等对象/数组存 TEXT，API 层 `json.dumps`/`json.loads`
- **布尔字段**：`isWorkday`、`isHoliday`、`absent` 存 INTEGER (0/1)，API 层转 `bool`

## 前端零改动清单

以下文件与 V2.0 **逐字节相同**（迁移时无需改动）：
- `shared/matcher.js`（数据匹配）
- `shared/layout.js`（侧边栏导航）
- `shared/bigsur.css`（设计系统）
- 所有 HTML 页面的 UI 结构

仅以下文件有数据层相关改动：
- `shared/db.js` → `shared/api-store.js`（Store 实现替换）
- `shared/auth.js`（JWT 登录）
- `shared/rules.js`（4 处复合索引查询）
- `shared/init.js`（兼容层简化为 Store 薄封装）
- `shared/excel.js`（`_apiExport` 增加 Authorization 头）
- 各 HTML 的 script 引用（移除 `dexie.min.js`，`db.js` → `api-store.js`）

## 验证要点

1. **导入验证**：6 个 Excel 文件（打卡/请假/加班/出差/漏打卡/排班）导入后条数与 V2.0 一致
2. **计算验证**：`RulesEngine.calculateMonth()` 结果与 V2.0 的 `attendance_results` 条数、状态分布一致
3. **导出验证**：平铺/日历导出 XLSX 内容与格式与 V2.0 一致（含条件格式、迟到/早退标红）
4. **设置验证**：考勤规则保存/读取、假期添加/删除、数据库重置正常
