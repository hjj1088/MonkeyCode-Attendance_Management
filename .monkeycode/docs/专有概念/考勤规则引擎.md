# 考勤规则引擎

## 概述

规则引擎 (`shared/rules.js`) 是系统的核心计算模块，负责将打卡数据、排班表、OA 申请数据综合处理，为每位员工每天产出考勤结果。

## 9 种状态体系

| 状态 | ID | 含义 | 判定条件 |
|------|-----|------|----------|
| normal | 正常 | 正常出勤 | 有打卡记录 且 无迟到/早退/旷工（或被容错豁免、或被请假分钟数覆盖） |
| rest | 休息 | 休息日 | 排班表标记为休息 (isWorkDay = false)；休息日打卡但未达加班起算时间时也归为 rest |
| abnormal | 迟到 | 异常迟到 | 签到晚于上班时间+阈值 且 请假分钟数 < 迟到分钟数（数值始终显示真实偏差） |
| early_leave | 早退 | 异常早退 | 签退早于下班时间-阈值 且 无迟到 且 请假分钟数 < 早退分钟数（v1.0.33 新增） |
| leave | 请假 | 请假 | 有对应日期的 leave_records 且 leaveDays >= 1 或 无打卡记录 |
| travel | 出差 | 出差 | 有对应日期的 travel_records |
| absent | 缺勤 | 旷工 | isWorkDay 且 (无打卡 或 半缺勤) 且 无请假/出差 且 漏打卡说明不覆盖缺失时段 |
| overtime | 加班 | 正式加班 | 休息日打卡 + 加班单时长 ≥ 加班起算时间 |
| suspect_ot | 疑似加班 | 休息日长时间打卡但无 OA | 休息日打卡跨度（首签退-首签到）≥ 加班起算时间 但 无达标加班单 |

> 历史文档曾列 `no_sign_in`/`no_sign_out` 两种细分状态，git 全历史中 rules.js 从未包含该实现，半缺勤（有打卡但缺单边）一直判定为 `absent`（v1.0.30 起按漏打卡说明时段细化），特此更正。

## isRestDay 与 status 的关系

这是两个易混淆的概念，在 v1.0.10 中已明确区分：

| 字段 | 含义 | 由什么决定 | OA 事件是否影响 |
|------|------|-----------|----------------|
| `isRestDay` | 排班列显示"休息"还是"上班" | **仅由排班表 + 假期管理** | 否 |
| `status` | 当天考勤结果状态 | 排班 + OA 数据 (漏打卡/请假/出差/缺勤) | 是 |

**示例**：某员工排班为休息日，但因漏打卡提交了说明——此时 `isRestDay = true`（排班休息），`status = normal`（漏打卡解释后状态正常）。排班列正确显示"休息"（而非被覆盖为"上班"），追溯弹窗可查看关联漏打卡记录。

## 迟到/早退判定

```js
// _calcDeviation(signIn, signOut, config)
if (signIn > workStartTime + lateThreshold) → lateMinutes = signIn - workStartTime
if (signOut < workEndTime - earlyThreshold) → earlyMinutes = workEndTime - signOut
```

阈值在设置页配置。每次打卡记录独立计算偏差，按天汇总。

## 容错豁免规则

每月迟到满足以下两个条件时，该员工所有迟到记录清零，状态恢复为 normal：

1. 迟到次数 ≤ `graceTimes` (默认 2 次)
2. 累计迟到分钟 ≤ `graceMinutes` (默认 30 分钟)

早退（`earlyRecords`）与迟到对称独立豁免（v1.0.33 起）。

豁免在 `calculateMonth()` 末尾对整月汇总后一次性执行，仅对出现在 `lateRecords`/`earlyRecords` 中的记录复位。

## 请假覆盖迟到/早退 (v1.0.34，替换 v1.0.30 抵扣实现)

当天存在请假记录（`dayLeaveRecords` 非空，按 `subject`/`applicant` 匹配实际人）时，请假分钟数只决定**状态**，数值始终显示真实打卡偏差：

```js
const leaveMinutesTotal = leaveHours * 60;

// 全天假（status = 'leave'）：迟到早退直接清零（保留行为）
if (isWorkDay && status === 'leave') {
  adjustedLateMinutes = 0;
  adjustedEarlyMinutes = 0;
}

// 迟到判定：请假分钟数 >= 迟到分钟数 → 状态保持 normal，迟到数值保留真实值
if (adjustedLateMinutes > 0 && hasRealPunch && isWorkDay && ...) {
  const coveredByLeave = !!(leaveRecord && leaveMinutesTotal >= adjustedLateMinutes);
  if (!coveredByLeave) { lateRecords.push(...); status = 'abnormal'; }
}

// 早退判定对称（status === 'normal' 时触发 early_leave）
```

- 迟到/早退分钟数永远按 `_calcDeviation` 真实偏差显示，无差值冲抵
- 场景：上班 8:30 + 签到 9:51（迟到 81min）+ 调休 1.5h → 状态「正常」、迟到显示 1h21m；迟到 86min + 请假 30min → 状态「迟到」+ 86min
- 历史：v1.0.30 曾实现「请假分钟抵扣迟到」（81min 被 1.5h 调休抵成 0），v1.0.33 取消抵扣改真实偏差，v1.0.34 定型为覆盖语义

## 请假时长按天分摊 (v1.0.31)

`_leaveHoursForDay(l)`：跨 N 天的请假记录（`startDate ~ endDate`）总时长分摊到每天，每天计 `total / N`（保留 2 位小数）；单天记录（`end <= start`）保持原值。`leaveHours` 为空时按 `leaveDays * 8` 取总时长再分摊。

- 结果行 `leaveHours` 为当天分摊值：2 天调休 16h → 每天各 8h（修复前每天全量 16h，两天合计 32h 并写进导出 Excel）
- 调休当日扣减同步用分摊值：`adjustedOvertime -= dayHours`（修复前每天扣全量，跨天调休导致加班结余被多扣）
- 月结余 `_updateCarryOver` 的 `adjustmentHours` 按记录全量累加一次，与逐日分摊合计守恒
- 跨月记录：`_matchOA` 仅匹配计算月内日期，分摊按记录全区间计算，总量守恒

## 同天多种请假分行 (v1.0.32)

同一天存在多条请假记录（如上午公休 2.5h + 下午调休 4h）时：

- `leaveType` 去重后用「、」拼接（「公休、调休」），供表格列/详情弹窗直接显示
- 新增 `leaveDetails` 字段：`[{type, hours}]` 数组，`hours` 为当天分摊值，合计等于 `leaveHours`
- 存储：`attendance_results.leaveDetails`（JSON 文本，`database.py` 对旧库 `ALTER TABLE` 补列；`server.py` `json_serialize` 读出时反序列化为数组）
- 展示：
  - 日历格（`AttendanceCalendar`）：leave 状态时按 `leaveDetails` 逐行渲染「类型 小时」
  - Excel 日历导出（`export.py` `_leave_lines`）：逐条「类型 h」用换行符拼接，单元格 `wrap_text`；旧结果（无 leaveDetails）回退 `leaveType/leaveHours` 单行
- 场景：公休 2.5h + 调休 4h → 格子两行「公休 2.5h / 调休 4h」，`leaveHours = 6.5`，调休扣减 4h

## 加班计算 (v1.0.34/v1.0.35)

加班只认加班申请单（OA `overtime_records`），打卡记录自带的 `punch.overtimeHours` 不计入（v1.0.34）：

```js
// 加班起算门槛 (v1.0.35)：overtimeThreshold 分钟（默认 30，规则设置页可配）
for (const o of dayOvertimeRecords) {
  if ((o.overtimeHours || 0) * 60 >= otMin) adjustedOvertime += o.overtimeHours || 0;
}
```

休息日打卡判定（v1.0.35）：
- 加班单时长 ≥ 起算时间 → `overtime`
- 无达标加班单但打卡跨度（首签退 - 首签到，单边打卡视为 0）≥ 起算时间 → `suspect_ot`
- 不足起算时间（如下班顺路打卡 2 分钟）→ `rest`

## 加班结余 (Carry Over)

每月计算一次结余：

```text
prevBalance = 上月结余 (查 carry_over 表, prevMonthKey 为 targetMonth 的上个月)
adjustmentHours = 本月调休请假消耗的小时数 (leaveType 含"调休"的 leaveHours 之和)
monthOvertime = 本月达标的 OA 加班单时长之和（≥ 起算时间；打卡自带加班不计，v1.0.34/v1.0.35）
newBalance = prevBalance + monthOvertime - adjustmentHours
```

结余不能为负数（`Math.max(0, newBalance)`）。

**prevMonthKey 查找**：向前查 2 个月（`month - 2`），因为当月 carry_over 在月计算完成后才会写入，不能引用自身。

## isWorkDay 判定

```js
_isWorkDay(schedulesData, holidaysData, dateStr)
```

优先级（从高到低）：
1. 假期管理中有该日期 → `holiday.isWorkday ? true : (holiday.isHoliday ? false : ...)`
2. 排班表 `workDays[day]` → `true` (上班) / `false` (休息)
3. 无排班数据 → 默认上班 (`return true`)

## 缺勤 (absent) 判定

两类缺勤判定（均在上班日）：

**完全无打卡**：同时满足 `isWorkDay`、`dayPunches.length === 0`、无请假、无出差、无漏打卡说明。

**半缺勤 (v1.0.30 时段细化)**：有打卡但缺单边（`!firstSignIn` 或 `!lastSignOut`）、无请假、无出差时：

- 缺上午打卡 → 需存在覆盖 am 的漏打卡说明（`_missCoversPeriod(m, 'am')`）
- 缺下午打卡 → 需存在覆盖 pm 的漏打卡说明
- 说明时段对不上（如缺上午打卡但说明写「下午」）→ 仍判 `absent`

## 漏打卡处理

- 完全无打卡 + 上班日 + 任一漏打卡 OA 记录匹配 → `status` 设为 `normal`（不影响 `isRestDay`）
- 半缺勤场景按 `_missCoversPeriod` 时段匹配（见缺勤判定）

人员匹配（v1.0.30 与 V3.3 导入层对齐）：`_oaNames(r)` 解析 `subject`（V3.3 导入的代申请实际人，缺省回退 `applicant`），支持逗号/顿号等分隔的多姓名；漏打卡记录额外并入 `missPerson`。日期条件为 `m.missDate === dateStr`。

## 调休请假扣减

当 `leaveRecord.leaveType` 包含"调休"关键字时：
- `adjustedOvertime = Math.max(0, adjustedOvertime - dayHours)`（从当日加班中扣除，下限钳制为 0，v1.0.33——此前无加班可扣时会出现 -1.5h 负数显示）
- 同时在 `_updateCarryOver()` 中从月结余扣除

## 时长显示格式 (V3.3.4)

`shared/constants.js` 的 `formatDuration(min)` 统一时长显示：`<60` 显示 `45m`，`≥60` 显示 `1h21m`（整点 `1h`，0 显示 `0m`）。WebUI 考勤主表、详情弹窗、个人考勤、关联打卡记录表格与日历 tooltip 统一使用；导出 Excel 的迟到/早退列保持数字分钟（便于筛选求和），颜色由条件格式动态判定。

## 工作时长计算 (v2.0 新增)

v2.0 在 `calculateMonth()` 的结果中新增 `workHours` 字段，记录员工每日实际工作时间：

```js
// rules.js: calculateMonth() 中
let workHours = 0;
if (firstSignIn && lastSignOut) {
  const [ish, ism] = firstSignIn.split(':').map(Number);
  const [osh, osm] = lastSignOut.split(':').map(Number);
  workHours = Math.round(((osh * 60 + osm) - (ish * 60 + ism)) / 60 * 100) / 100;
}
```

工作小时数精确到 0.01 小时，仅在同时有签到和签退时计算。该字段存储于 `attendance_results` 表，支持导出时作为模板字段使用。

`init.js` 桥接层中的 `AttendanceMatcher.match()` 同样输出 `workHours` 字段，计算方式相同（通过 `init.js` 中的 `hours` 变量）。

## 配置变更检测 (v1.0.10)

考勤页面加载时自动检测：
- `settings` 表中 `config_updated_at` 时间戳
- 对比 `last_calc_{YYYY-MM}` 时间戳
- 若配置变更时间晚于最后计算时间 → 显示黄色横幅提示重新计算
