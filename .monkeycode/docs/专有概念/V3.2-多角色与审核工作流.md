# V3.2 多角色与审核工作流

> 版本标记：v3.2。描述多角色权限模型与考勤审核状态机的设计与实现依据（代码位置见末尾）。

## 角色模型

| 角色 | 枚举值 | 数据范围 | 前端默认页 | 后端鉴权 |
|------|--------|----------|------------|----------|
| 人事管理员 | `hradmin` | 全部数据 | `/attendance` | `_require_hradmin` |
| 部门管理员 | `deptadmin` | 本部门 | `/attendance` | `_require_any_user` + 部门过滤 |
| 员工 | `employee` | 本人 | `/my` | `_require_any_user` |

### 权限边界

- **前端**：`router/index.js` 的 `beforeEach` 守卫校验登录态与角色；`AppSidebar.vue` 按角色过滤菜单
- **后端**：每个 handler 独立调 `verify_token` + 角色/部门检查，不信任前端传参（deptadmin 的部门取自 token payload，而非请求体）
- **敏感接口**：`/api/users`、`/api/system/*`（除 version）、`/api/rules/*`、`/api/migrate`、`/api/attendance/lock` 仅 hradmin；`/api/attendance/all` 对 employee 返回 403

## 审核状态机

```
pending_review ──确认(confirmed)──► confirmed ──部门/人事提交──► submitted ──锁定──► locked
      ▲                              │  ▲
      └────────────申诉(disputed)────┘  └──────────再次确认(confirmed)──────────┘
```

| 当前状态 | 允许变更 |
|----------|----------|
| `pending_review` | `confirmed`, `disputed` |
| `confirmed` | `disputed` |
| `disputed` | `confirmed` |
| `submitted` | （终态） |
| `locked` | （终态） |

### 流转规则

1. **确认/申诉**：`PATCH /api/attendance/{id}/review`，仅 deptadmin/hradmin；非法流转返回 400
2. **部门提交**：`PATCH /api/attendance/dept/submit` 仅处理本部门/全量 `confirmed` 记录；deptadmin 只能提交自己部门
3. **锁定**：`PATCH /api/attendance/lock`（仅 hradmin），要求该月全部记录已 `submitted`，否则返回 400
4. **审计**：每次状态变更写入 `operation_logs`（username/action/detail JSON）

## 强制改密

- 判定：登录时 `admin` 用户密码仍为 bcrypt(`admin123`) → 响应 `need_change_password: true`
- 前端：`LoginView` 检测该标志跳转 `/setup`（`SetupWizardView` 两次输入一致校验）
- 后端：`POST /api/auth/change-password`（校验旧密码 + 新密码 ≥6 位）

## 登录锁定

`users.login_attempts` 累计失败次数，满 5 次写 `locked_until`（30 分钟）；`locked_until` 过期后自动清除。管理员忘记新密码时可清空 `login_attempts`/`locked_until` 并重置 `password_hash` 为初始密码解锁。

## 测试数据

`POST /api/system/seed-test-data`（hradmin）生成：3 部门 × 5 员工 + 3 部门管理员，员工密码统一 `test123`；当月工作日打卡 + 每人一条年假。`POST /api/system/reset-data` 清空业务表（punch/leave/overtime/travel/miss_punch/schedules/attendance_results/carry_over/raw_files/employees），保留 `users`/`settings`。
