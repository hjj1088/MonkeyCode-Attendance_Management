# V3.2 多角色与审核工作流

> 版本标记：v3.2。描述多角色权限模型与考勤审核状态机的设计与实现依据（代码位置见末尾）。

## 角色模型

| 角色 | 枚举值 | 数据范围 | 前端默认页 | 后端鉴权 |
|------|--------|----------|------------|----------|
| 超级管理员 | `superadmin` | 全部数据 | `/attendance` | `_require_superadmin` / `_require_admin` |
| 人事管理员 | `hradmin` | 全部数据 | `/attendance` | `_require_admin` |
| 部门管理员 | `deptadmin` | 本部门 | `/attendance` | `_require_any_user` + 部门过滤 |
| 员工 | `employee` | 本人 | `/my` | `_require_any_user` |

### 权限边界

- **前端**：`router/index.js` 的 `beforeEach` 守卫校验登录态与角色；`AppSidebar.vue` 按角色过滤菜单
- **后端**：每个 handler 独立调 `verify_token` + 角色/部门检查，不信任前端传参（deptadmin 的部门取自 token payload，而非请求体）
- **敏感接口**：`/api/system/*`（除 version/config）、`/api/migrate` 仅 superadmin；`/api/users`、`/api/rules/*`、`/api/attendance/lock` 为 hradmin/superadmin；hradmin 列表不可见 superadmin，不可创建/管理 superadmin；`/api/attendance/all` 对 employee 返回 403

## 审核状态机

```
pending_review ──确认(confirmed)──► confirmed ──部门/人事提交──► submitted ──锁定──► locked
      ▲                              │  ▲
      └────────────申诉(disputed)────┘  └──────────再次确认(confirmed)──────────┘
```

| 当前状态 | 允许变更 |
|----------|----------|
| `pending_review` | `confirmed`, `disputed` |
| `confirmed` | `disputed` |
| `disputed` | `confirmed` |
| `submitted` | （终态） |
| `locked` | （终态） |

### 流转规则

1. **确认/申诉**：`PATCH /api/attendance/{id}/review`，deptadmin/hradmin/superadmin；非法流转返回 400
2. **部门提交**：`PATCH /api/attendance/dept/submit` 仅处理本部门/全量 `confirmed` 记录；deptadmin 只能提交自己部门
3. **锁定**：`PATCH /api/attendance/lock`（hradmin/superadmin），要求该月全部记录已 `submitted`，否则返回 400
4. **审计**：每次状态变更写入 `operation_logs`（username/action/detail JSON）

## 强制改密

- 判定：`admin` 且角色 `superadmin`，密码仍为 bcrypt(`admin123`) → 响应 `need_change_password: true`
- 前端：`LoginView` 检测该标志跳转 `/setup`（`SetupWizardView` 两次输入一致校验）
- 后端：`POST /api/auth/change-password`（校验旧密码 + 新密码 ≥6 位）

## 登录锁定

`users.login_attempts` 累计失败次数，满 5 次写 `locked_until`（now + 1 天，提示「锁定24小时」）。每次失败更新 `last_failed_login`。登录前 `clear_stale_attempts`：距上次失败超过 1 天则清零计数。`locked_until` 过期由 `clear_locked_if_expired` 清除。解锁：清空 `login_attempts`/`locked_until` 并重置 `password_hash`。

## 测试数据

`POST /api/system/seed-test-data`（superadmin）生成：3 部门 × 5 员工 + 3 部门管理员；当月工作日打卡 + 每人一条年假。`POST /api/system/reset-data` 清空业务表（punch/leave/overtime/travel/miss_punch/schedules/attendance_results/carry_over/raw_files/employees），保留 `users`/`settings`。

## 代码位置

- 状态机：`server/handlers/attendance.py` `handle_attendance_review`
- 角色鉴权：`server/middleware.py`、`server/server.py` do_GET/do_POST/do_PATCH

- 数据库：`server/database.py`（users.login_attempts / locked_until / last_failed_login、operation_logs、attendance_results 审核列）
- 相关测试：`tests/test_auth.py`、`tests/test_users.py`、`tests/test_workflow.py`、`tests/test_data_management.py`

## SPA 无 token 刷新

无 token 刷新任意业务路径：`defaultPath()` 直跳 `/login`。`showLayout` 在路由未匹配时为 false，侧栏不先闪。Vite 对 `/attendance` 等前缀强制 `index.html`，避免旧 `attendance.html`（侧栏「考勤管理」、顶栏问候语）。
