# V3.1 后端服务模块

> v3.1（`attendance-v3/server/`）的后端服务。由 `server.py`（HTTP 入口 + 路由 + 认证 + 静态托管）、`database.py`（SQLite 数据层）和 `handlers/export.py`（导出处理器）组成。

## 文件职责

| 文件 | 行数 | 职责 |
|------|------|------|
| `server.py` | 477 | HTTP 服务、路由分发、JWT 认证、通用 store CRUD、静态文件托管 |
| `database.py` | 251 | SQLite 连接、13 表 DDL、17 个索引、默认数据初始化 |
| `handlers/export.py` | 477 | XLSX 导出（`build_flat_report` / `build_calendar_report`，移植自 V2.0） |
| `middleware.py` | 76 | PyJWT 认证模块（**备用，未接入 server.py**） |
| `handlers/auth.py` 等 6 个 | — | 第二套 handler（**未接入路由**） |

## server.py

### 认证

- 手写 JWT：`b64url_encode/decode` + HMAC-SHA256 签名
- `generate_token(username)`：HS256，payload 含 `username`/`iat`/`exp`，有效期 24 小时
- `verify_token(token)`：HMAC 校验 + 过期检查（`hmac.compare_digest`）
- 登录：`POST /api/auth/login`，仅校验内置 `admin`（密码 `admin123` 的 SHA256 哈希比对）

### 通用 store CRUD

`_handle_store_*` 系列方法实现 13 张表的通用读写：

- `GET /api/store/{table}`：全表查询，可选 `?index=&value=` 单列过滤
- `GET /api/store/{table}/range?index=&lower=&upper=`：范围查询
- `GET /api/store/{table}/{key}`：按主键（settings 按 `key`，其余按 `id`）
- `POST /api/store/{table}`：upsert（有 id 更新，无 id 插入）
- `POST /api/store/{table}/bulk`：批量插入，返回 `{count}`
- `DELETE /api/store/{table}`：清空整表
- `DELETE /api/store/{table}/{key}`：按主键删除
- `POST /api/store/reset`：清空 13 表后重建默认设置

### JSON 序列化（`json_serialize`）

- `workDays`、`fields`、`source*Ids`、`value` 等 JSON 字段读写时自动 `json.dumps`/`json.loads`
- `isWorkday`、`isHoliday`、`absent` 等布尔字段存 INTEGER，读出转 `bool`

### 静态托管（`_serve_static`）

- 非 `/api` 路径映射到 `../client/` 目录
- 路径穿越防护：`os.path.normpath` + `startswith` 前缀校验
- MIME 映射：html/css/js/json/png/jpg/ico
- 文件不存在 → 302 重定向 `/index.html`（SPA 回退）

## database.py

### SQLite 连接（`get_db`）

- 路径：`server/data/attendance.db`（自动创建目录）
- `row_factory = sqlite3.Row`
- PRAGMA：`journal_mode=WAL`、`busy_timeout=5000`、`synchronous=NORMAL`、`foreign_keys=OFF`

### SQLite 表结构

13 张表，字段名与 V2.0 IndexedDB 完全一致（camelCase）：

| 表名 | 主键 | 关键字段 |
|------|------|----------|
| `raw_files` | id | fileName, fileType, recordCount, importTime |
| `punch_records` | id | employeeNo, customNo, name, date, period, scheduleStart, scheduleEnd, signIn, signOut, lateMinutes, earlyMinutes, absent, overtimeHours, workHours, department, isWeekday, isWeekend, isHoliday, weekdayOT, weekendOT, holidayOT |
| `leave_records` | id | applicant, department, leaveType, startDate, endDate, leaveDays, leaveHours, reason |
| `overtime_records` | id | applicant, department, startTime, endTime, overtimeHours, content |
| `travel_records` | id | applicant, department, destination, travelers, startDate, endDate, travelType, reason |
| `miss_punch_records` | id | applicant, department, missDate, missPerson, missTime, cardTime, reason |
| `schedules` | id | employeeNo, name, department, year, month, workDays (JSON) |
| `attendance_results` | 无 | employeeNo, name, department, date, period, scheduleStart, scheduleEnd, signIn, signOut, lateMinutes, earlyMinutes, overtimeHours, travelHours, leaveHours, workHours, absent, status, leaveType, isRestDay, month, missTime, sourcePunchIds/sourceLeaveIds/sourceTravelIds/sourceMissIds/sourceOvertimeIds (JSON) |
| `carry_over` | 无 | employeeNo, name, month, overtimeBalance |
| `holidays` | id | date, name, isWorkday, isHoliday |
| `settings` | key | value (JSON) |
| `export_templates` | id | name, isDefault, fields (JSON) |
| `employees` | employeeNo | name, department |

17 个索引覆盖常用查询列：`employeeNo`、`date`、`applicant`、`startDate`、`month`、`department` 等，以及 `schedules(employeeNo,year,month)`、`attendance_results(employeeNo,date)`、`attendance_results(month)`、`carry_over(employeeNo,month)`、`holidays(date)`、`employees(name)` 等复合索引。

> 注意：`attendance_results` 与 `carry_over` 无 `id` 主键——V2.0 中它们使用业务键（`[employeeNo+date]`、`[employeeNo+month]`）作为主键，SQLite 中改为无主键 + 索引 + 应用层约束。

### 默认数据初始化（`_init_settings`）

1. `settings['attendance_config']`（仅当不存在）：
   ```json
   {"workStartTime":"08:30","workEndTime":"17:30","lateThreshold":0,"earlyThreshold":0,"graceTimes":2,"graceMinutes":30}
   ```
2. `export_templates` 默认模板（仅当无 `isDefault=1`）：`默认模板`，17 个字段（序号/考勤号码/姓名/部门/日期/对应时段/上班时间/下班时间/签到时间/签退时间/迟到时间/早退时间/加班时间/出差时间/请假类型/请假小时/是否旷工）

## handlers/export.py

移植自 V2.0 `export_server.py`，逻辑一致：

### build_flat_report（平铺导出）

- Sheet 名"考勤记录"，表头取 `template.fields[].label`
- 状态映射中文：`normal→正常`、`abnormal→迟到`、`leave→请假`、`travel→出差`、`absent→缺勤`、`no_sign_in/no_sign_out→缺勤`（V3.1.1 起规则引擎不再产生，历史数据按缺勤展示）、`overtime/suspect_ot→疑似加班`
- `_get_cell_style`：含 假/休/出差/加班/补卡 → 蓝字；含 迟/早/未打卡/缺勤/漏打卡 → 红字
- 签到晚于上班、签退早于下班 → 标红
- openpyxl `FormulaRule` 条件格式（`TIMEVALUE(cell)>TIME(...)`）
- 列宽按字符宽度自适应（中文按 2 计，上限 40）

### build_calendar_report（日历导出）

- Sheet 名"`{y}年{m}月考勤明细`"，`monthrange` 求当月天数
- 表头两行：部门（合并单元格）+ 员工姓名；前三列 日期/排班/打卡时间（A、B 纵向合并）
- 每天两行：上午（`build_am_cell`）+ 下午（`build_pm_cell`），格子优先级：请假标注 → 打卡时间 → 出差标注 → 漏打卡 → 缺勤 → 空
  - 有打卡 → 显示签到/签退时间
  - 请假（status=leave 或 leaveType 有值）→ `类型/时长h`，上下午都补文字
  - 出差（sourceTravelIds 有值）无打卡 → `出差/时长h`；有打卡 → 打卡侧显示时间，缺失侧自动显示出差信息
  - 漏打卡（missTime 匹配上午/下午）→ `漏打卡`
  - 缺勤（absent 或 status=absent/no_sign_in/no_sign_out）→ `缺勤`，上下午都补文字
  - 休息日（status=rest）→ 空
- 休息日整行灰底；迟到/早退单元格标红；数据区追加 `FormulaRule` 条件格式
- 响应头 `Content-Disposition` 用 `filename*=UTF-8''`（RFC 5987）支持中文文件名

## 未接入的代码（如实说明）

`handlers/auth.py`、`attendance.py`、`rules.py`、`system.py`、`users.py`、`migrate.py` 及 `middleware.py` 存在但**未挂载到任何路由**。它们属于另一套（V3.2 多角色系统）的代码，依赖 `users` 表、`operation_logs` 表及 snake_case 字段，当前 `database.py` 的 13 张 camelCase 表不提供这些结构。`server.py` 实际只导入 `handlers/export.py`。
