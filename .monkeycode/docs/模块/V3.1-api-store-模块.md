# V3.1 api-store 模块

> v3.1（`attendance-v3/client/shared/api-store.js`）前端数据访问层。替代 V2.0 的 `db.js`，保持 `Store` 对象接口签名完全一致，内部实现从 Dexie 表操作改为 `fetch` 调用后端 REST API。

## 定位

V2.0 中业务代码统一通过 `Store` 对象访问 IndexedDB。V3.1 创建同名的 `api-store.js`，实现相同接口，从而**业务代码零改动**即可从本地存储切换到远程后端：

```
V2.0: 业务代码 → Store.xxx() → Dexie → IndexedDB
V3.1: 业务代码 → Store.xxx() → fetch → /api/store/* → SQLite
```

## 核心实现

### `_request(path, options)` — 统一请求封装

所有 Store 方法内部经它发起请求：

1. 从 `sessionStorage.token` 读取 JWT
2. 自动附加 `Content-Type: application/json` 与 `Authorization: Bearer <token>` 头
3. 响应 401 → 清除 token/user，跳转 `index.html`，抛 `Unauthorized`
4. 非 2xx 或 `body.code !== 0` → 抛 `body.message`
5. 成功返回 `body.data`

### `_clean(value)` — JSON 深拷贝

`JSON.parse(JSON.stringify(value))` 防止并发修改污染调用方数据（对应 V2.0 文档中记录的 Dexie `bulkPut` 副作用规避）。

## Store 方法清单

| 方法 | 内部 REST 调用 | 返回 |
|------|---------------|------|
| `bulkPut(table, records)` | `POST /api/store/{table}/bulk`，body `{records}` | `data.count`（写入条数） |
| `clearTable(table)` | `DELETE /api/store/{table}` | — |
| `getAll(table)` | `GET /api/store/{table}` | 记录数组 |
| `getByIndex(table, index, value)` | `GET /api/store/{table}?index=&value=` | 过滤数组；value 为空直接返回 `[]` |
| `getByRange(table, index, lower, upper)` | `GET /api/store/{table}/range?index=&lower=&upper=` | 范围过滤数组 |
| `getByKey(table, key)` | `GET /api/store/{table}/{key}` | 单条记录 |
| `put(table, record)` | `POST /api/store/{table}`，body `{record}` | — |
| `deleteByKey(table, key)` | `DELETE /api/store/{table}/{key}` | — |
| `resetAllData()` | `POST /api/store/reset` | — |

## 自动初始化

`api-store.js` 文件末尾自动执行：`Store.getByKey('settings', 'attendance_config')` 不存在时写入默认考勤规则：

```js
{
  workStartTime: '08:30', workEndTime: '17:30',
  lateThreshold: 0, earlyThreshold: 0,
  graceTimes: 2, graceMinutes: 30
}
```

> V2.0 该逻辑在 `db.js startDB()` 中；V3.1 迁移到前端 `api-store.js`，同时后端 `database.py _init_settings()` 也会初始化，双重保障。

## 与 V2.0 db.js 的差异

| 维度 | V2.0 `db.js` | V3.1 `api-store.js` |
|------|-------------|---------------------|
| 依赖 | Dexie.js（`dexie.min.js`） | 无（原生 `fetch`） |
| 存储 | IndexedDB | 后端 SQLite |
| 认证 | 无 | 自动附加 Bearer JWT |
| 401 处理 | 无 | 清除凭证 + 跳转登录页 |
| `resetAllData` | 前端遍历清空 13 表 | 后端单端点 `POST /api/store/reset` |
| `_clean` | 仅 `bulkPut` 前使用 | 所有写操作前统一使用 |

## 页面引用变更

所有 HTML 页面的 script 引用变化：

- **移除**：`<script src="shared/dexie.min.js">` 和 `<script src="shared/db.js">`
- **新增**：`<script src="shared/api-store.js">`

受影响页面：`attendance.html`、`import.html`、`export.html`、`settings.html`（`index.html`、`login.html` 仅移除 dexie，无需 api-store）。

## 使用示例

```js
// 导入打卡记录
await Store.bulkPut('punch_records', parsedRecords);

// 查询某员工某月考勤结果
const results = await Store.getByIndex('attendance_results', 'month', '2026-07');
const mine = results.filter(r => r.employeeNo === '001');

// 读取/保存设置
const config = await Store.getByKey('settings', 'attendance_config');
await Store.put('settings', { key: 'attendance_config', value: newConfig });

// 重置全部数据
await Store.resetAllData();
```
