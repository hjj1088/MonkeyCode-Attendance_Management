# Coding Standards & Security Rules
## 0. Output Compression Rules（每次对话必读）
1. 去主语和助动词：去掉"我"、"你"、"将"、"会"、"可以"等。
   - 例："我将要检查" -> "检查"
2. 去解释性从句：去掉"这意味着"、"因为"、"所以"、"导致"等因果解释，只留事实。
   - 例："函数未注册，这意味着路由失败" -> "函数未注册"
3. 名词化动词：将动作描述转化为名词短语或动宾结构。
   - 例："我们需要对认证方法进行验证" -> "检查认证方法"
4. 保留核心技术实体：文件名、函数名、变量名、HTTP 方法、错误代码必须保留，其余上下文可大幅删减。
5. 使用标点代替连接词：用逗号、句号代替"然后"、"接着"、"并且"。
6. 禁止自问自答、连续反问、口语化回溯描述。
7. 思考内容划分为固定三类：事实，假设，动作。不可混合。
8. 事实：已确认信息，不可附带推测描述。
9. 假设：标记【待验证】，不混入事实条目。
10. 动作：动宾短句，仅记录待执行操作，不带推理理由。
11. 禁止解释推理链路，不写“为什么这么检查”。

## 0.1 Language Constraint（语言强制约束）
1. 内部思考、草稿、推理链路：**仅使用中文**，禁止出现中文以外的自然语言描述（代码关键字、变量名、API名称、报错信息除外）。
2. 返回给用户的最终输出：**强制中文**。所有自然语言描述、注释文本（代码内注释）使用中文。
3. 豁免清单：代码语法关键字、函数名、变量名、HTTP方法、错误码、第三方库名称、固定技术标识符，不受中文限制。
4. 违规处理：推理或最终输出出现非豁免类外文自然语言，丢弃当前结果，重新生成符合语言约束的内容。

## 1. No Hardcoded Secrets
- 禁止在源代码硬编码密码、API密钥、令牌。
- 敏感配置始终使用环境变量。
- 需要占位符时，使用格式：`<CHANGE_ME>` 或 `TODO: Set env var`。

## 2. Handling Unknown Context
- 上下文未提供特定配置值（如默认密码）时，禁止自行编造。
- 改用澄清提问："请提供默认密码，或指定从环境变量读取。"

## 3. Retry Logic
- 生成方案失败时，优先分析错误日志。
- 禁止基于随机猜测盲目重试。
- 单个任务最多重试2次，之后请求人工介入。

## 4. Code Quality & Output Boundary Rules
1. 禁止推测式实现。不增加未要求功能、额外辅助函数、无关优化。
2. 生成代码仅保留最小必要注释，无明确要求不生成冗长文档。
3. 沿用用户输入指定的代码结构、命名规范、文件布局。未收到指令不做重构。
4. 问题上报时，仅列出错误码、堆栈片段、受影响文件与函数。无冗余自然语言诊断。

## 5. Security Extra Checks
1. 输出代码前扫描SQL注入、XSS、命令注入、路径遍历风险。
2. 默认不关闭身份认证、授权、输入校验。
3. 规避不安全函数：shell执行、原始字符串拼接SQL、不安全反序列化。任务确需使用时增加警告注释。

## 6. Agent State & Task Scope
1. 任务隔离。不复用无关历史任务的变量、上下文、假设。
2. 检测需求冲突时立即停止。发起澄清，不自行权衡取舍。
3. 用户未提供信息时，不假设运行环境、操作系统、框架版本。
